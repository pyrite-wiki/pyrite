- A rubric checker now sees an item's fields wherever the index keeps them, so a criterion gives the same verdict in a `board.yaml` gate as in `pyrite qa validate` (#1587).
  - Gates (`sw_check_ready`, `sw_claim`, `sw_transition`, `sw_review` when approving, `sw_refine`, and their `pyrite sw` commands) now pass `priority_present`, `has_field` and `has_any_field` for `priority`, `status`, `assignee`, `summary`, a date or `tags`, and pass `has_tags` and `has_outlinks`, for an item that has them. Before, these failed for every item, so an `enforce` gate naming one could never pass.
  - `pyrite qa validate` (and `pyrite ci`, MCP `kb_qa_validate`, the REST QA routes) no longer reports a missing priority, status, assignee or tags for an item that has them. It no longer reports "no parent epic" for an item with a `subtask_of` link, or "consider decomposing" for an XL item with a `has_subtask` link.
  - A checker sees a field as Pyrite reads it, the value `pyrite get` shows, which can be the item type's default when the file leaves the field out. So these now hold for every item of the type, in a gate and in QA: `priority_present` and `has_field priority` on a `backlog_item` (default `medium`) and on a `task` (default `5`); `has_field status` on a type that defaults its status (for example `backlog_item`, `task`, `adr`, `design_doc`, `milestone`, `event`); and `has_field importance` and `has_field lifecycle` on every item. A checker cannot yet tell a defaulted field from a written one (#1695). A field the type declares is read at its own name, as `get` shows it, even when a `metadata:` spelling holds another value: a backlog item with `priority: ""` and `metadata: {priority: high}` has no priority, and a `task`'s `date`, `start_date`, `end_date` and `assigned_at`, which the task model does not read from its file, are missing to a checker as they are at their own names in `get`. An empty value written in the file (`priority: ""`) is missing, for every kind of type.
