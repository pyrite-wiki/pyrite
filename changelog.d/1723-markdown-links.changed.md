- A Markdown link from an entry body to an entry file in the same KB (`[text](other.md)`, `[text](../folder/other.md#heading)`, angle form, title, `%20`, reference-style; `[text](other)` when `other.md` exists) is now a link row with relation `markdown_link` (inverse `markdown_linked_by`), so `backlinks`, the graph, `links check`, `index health` and QA see it like a wikilink. The row names the entry indexed at that path now, whatever order files are written in: an id change with the file kept is followed, and a moved or deleted target makes it broken. URLs, images, links in code, self-links, root-relative or absolute paths, paths that leave the KB and paths the index walk does not list (`README.md`, `_templates/`, hidden folders) are not links; a listed `.md` file that is not indexed as an entry gives a broken link, and a link spelled in another case than the file is broken. The index schema moves to v30 (`link.target_path`), and its first open (SQLite's migration, or Postgres's startup when the column is new) marks every entry to be read once, so the first `pyrite index sync` after upgrading reads every file and reports nothing changed. After that sync, `backlinks` and the graph may grow, and `pyrite links check` may newly exit 1: an in-KB `.md` link with nothing at its path is a broken link (#1723).
