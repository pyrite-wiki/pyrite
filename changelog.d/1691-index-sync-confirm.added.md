- `pyrite index sync -k <kb> --confirm <id-or-path> ...` syncs, then says for each named entry whether it is indexed and searchable: one row per name with a `status` (`indexed`, `not_indexed`, `not_found`, `malformed`, `duplicate`, `skipped`), its schema findings, and its embedding state (`embedded`, `queued`, `unavailable`; never waited on). It exits 0 when every named entry is confirmed and 3 when any is not, a schema error on a named entry included. A path relative to the KB's folder confirms a file with no `id:`; `--confirm` alone confirms every entry the sync added or changed, reporting schema findings without failing. MCP `kb_index_sync` takes `confirm: [names]` and REST `POST /api/index/sync` takes `confirm` (with `wait=true` and the new `kb`), returning the same rows. `--confirm` with `--background` is refused (#1691).
- The sync result (`IndexManager.sync_incremental`, `reconcile_kb`, and `pyrite index sync --format json`) lists the entries it changed under a new `changed` key, `{kb, id, path, change}` (#1691).
