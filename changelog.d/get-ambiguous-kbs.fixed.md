- **An entry or task id in more than one KB is refused, not answered from the first KB in config order (#528).** Given without a KB (or with a blank `-k`/`kb`/`kb_name`), an id held by more than one KB you can read answers `AMBIGUOUS` with the KBs in `candidate_kbs`: CLI `get`, `task get`, `task status`, `pyrite-read get`, and `update`/`links suggest`/`links discover` given `-k ""`; MCP `kb_get`, `kb_read_body`, `task_status` and the task-graph tools, the `summarize_entry` and `find_connections` prompts and the `pyrite://entries/{id}` resource; REST blocks, collections and AI routes given a blank `kb` (`409`). A KB you cannot read is never listed and never makes an id ambiguous. Name the KB to choose: `-k`, `kb`, `kb_name`, the new `kb_a`/`kb_b` arguments of `find_connections`, or the new `pyrite://kbs/<kb>/entries/<id>` resource. REST `GET /api/entries/{id}` without `kb` still answers the first readable match until web links carry the KB (#910); extension commands' own lookups are #911.
