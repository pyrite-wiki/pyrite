- **A single-entry read returns what the entry's file holds now, on every surface (#753).** `pyrite get`, `pyrite-read get`, REST `GET /api/entries/{id}`, MCP `kb_get` and `kb_read_body` read the file instead of the index row, so a hand edit, another tool's edit or a `git pull` shows up before the next `index sync`, and a `get` followed by `update --body-file` no longer drops a section written by hand. Body, title, tags and every frontmatter field come from one parse of the file; links, backlinks and `indexed_at` stay the index's. The read carries `content_hash`, the SHA-256 of the bytes it read (ADR-0042 decision 9). An entry whose file is gone, or now holds another id, answers `NOT_FOUND` instead of the index's old copy. Thanks to @sb123sb123, whose #754 found the CLI case and its regression test. An update that echoes a read taken before a hand edit now writes over that edit, because the echo is compared with the file, not the stale row; `kb_update` does not check `content_hash` yet (ADR-0042 decision 11).
