`--fields` is now honoured in CSV, Markdown and Rich output, not only JSON and YAML: `search`, `recent`, `list-entries`, `batch-read` and `get`, and REST search, `GET /entries/{id}` and `POST /entries/batch` with `Accept: text/csv` or `text/markdown`, print the identity columns `id` and `kb_name` first and then the requested fields in the order given, with a column for a field no record has (`text/yaml`, like JSON, omits a key a record lacks). The `fields` list of `POST /entries/batch` is now cleaned like `?fields=` (spaces and duplicates dropped). Two Markdown shapes change under `--fields`: a single entry (`get X --fields title,body --format markdown`, or `GET /entries/{id}?fields=...` as `text/markdown`) is a one-row table with the body flattened instead of a frontmatter block plus body, and an empty result is an empty string instead of `# Search: q (0 results)`. A Rich table is printed only when the `id` and every header fit the console width whole; narrower, each record prints as `field: value` lines (separated by a blank line) instead of cells cut with `…`. Rich takes its width from the console: from the terminal even when stdout is piped, 80 when no standard stream is a terminal, `COLUMNS` overriding both. Scripts should use json, yaml or csv. `search --files` and the Rich file-search fallback still print their own table and now say on stderr that `--fields` is not applied. A `POST /entries/batch` `fields` list that cleans to nothing (`[""]`) still returns `id` and `kb_name` only.
