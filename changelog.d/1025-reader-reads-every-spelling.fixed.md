- **A field spelled only under `metadata:` is read (#1025).** ADR-0051 made `metadata.k` a second spelling of field `k`, and every write already landed where the file spells the field; the reader now reads it there too. A file with `metadata: {importance: 8}` and no top-level `importance:` reads 8 in the model, the index row, `pyrite get`, MCP `kb_get`, REST `GET /api/entries/{id}` and search, so `update -f importance=8` then `get` agree; `metadata.links` is indexed as outgoing links and backlinks, and `pyrite link` appends there instead of refusing. A read carries the field at its own key and the file's nested spelling under `metadata`, so echoing either back changes nothing. The hand-written list of five keys lifted out of `metadata` (`rank`, `effort`, `kind`, `status_reason`, `parked_awaiting`) is replaced by one rule: every field the entry's type declares is read at its own name, and a key the type does not declare stays under `metadata` (`parked_awaiting` on a task; `rank` on a type that has no such field). `provenance`, which no read carried, is read like every other field.
