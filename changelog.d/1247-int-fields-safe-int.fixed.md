Integer fields read from a file no longer make it fail to load on `.inf`, `.nan` or a word: `rank` and `adr_number` (software-kb), `reputation` and `writeup_count` (social), and `_schema_version` in the schema migration check and in QA validation now go through `safe_int` and fall back to the default. Before, a `backlog_item` with `rank: .inf` was refused as unreadable and left out of `sw backlog`, and a versioned type with `_schema_version: .inf` answered `get` with "not found". A test enumerates every integer field of the registered entry types so a new one cannot skip the rule.
