- A credential that does not verify now gets 401 where it used to be served as anonymous: with `anonymous_tier` set, a wrong, empty, expired or revoked API key (`X-API-Key`, `Authorization: Bearer`, or `?api_key` on REST and the live-update socket) or session cookie is refused on REST, `/mcp` and the live-update socket instead of silently getting the anonymous visitor's access. Only a request with no credential is anonymous. A wrong key next to a valid cookie is refused too. REST now accepts `Authorization: Bearer` carrying an API key or a session token, as `/mcp` does. Two setups that worked before are now refused: a deployment whose proxy adds its own `Authorization: Bearer` header while clients send `X-API-Key` (Bearer is read first on REST and `/mcp`); and two auth-enabled Pyrite instances on one host: browsers do not separate cookies by port, so each instance receives the other's `pyrite_session`, refuses it with 401, and (on REST) clears it, which signs the user out of the other instance.
