- A credential that does not verify now gets 401 where it used to be served as anonymous: with `anonymous_tier` set, a wrong, empty, expired or revoked API key (`X-API-Key`, `Authorization: Bearer`, `?api_key`) or session cookie is refused on REST, `/mcp` and the live-update socket instead of silently getting the anonymous visitor's access. Only a request with no credential is anonymous. A wrong key next to a valid cookie is refused too, and a 401 caused by the session cookie clears it. REST now accepts `Authorization: Bearer <key>`, as `/mcp` does. (#1754)
