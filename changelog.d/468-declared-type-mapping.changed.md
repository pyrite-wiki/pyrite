- **A create stores the type you named (#468).** Pyrite used to store a named core type as the KB plugin's most-derived subclass of it, so in a `kb_type: software` KB a `note` (the web form's default, a REST daily note, `pyrite create -t note`, MCP, import) was written as an ADR under `adrs/` with `adr_number: 0`; zettelkasten, encyclopedia and social KBs turned `note` into `literature_note`, `article` and `writeup`, and software and social KBs turned `document` and `person` into `design_doc` and `user_profile`. Now a type is mapped only when a plugin declares it with the new optional `get_type_mappings()` (journalism-investigation keeps `event` → `investigation_event` and `document` → `document_source`), the same on every create surface, `pyrite add FILE` included. `kb_schema`, `orient` and `GET /api/kbs/{kb}/schema` show the mappings as `type_mappings`. A mapping whose target the KB's `kb.yaml` does not declare is refused `UNDECLARED_TYPE`, and two plugins mapping one core type are refused at load. Entries already on disk keep their type. An out-of-tree plugin that relied on the inference stores the caller's type until it declares the mapping.
