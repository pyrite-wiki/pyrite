- `pyrite mcp-setup` registers the Pyrite MCP server where each client reads it. Before, it wrote `~/.claude/claude_desktop_config.json`, which no client reads. Claude Code gets it through `claude mcp add -s user` (or `./.mcp.json` with `--project`), and Claude Desktop in its own `claude_desktop_config.json` (macOS `~/Library/Application Support/Claude/`, Windows `%APPDATA%\Claude\`). With no `--client`, every client found is configured and named. The entry runs this install's `pyrite` by absolute path with an explicit `--tier`, default `write`. Before, it registered `pyrite-admin mcp`, which served the admin tier, and fell back to a bare `python` when `pyrite-admin` was not on `PATH`. The command checks that the server starts before writing. With no client found it exits 1 and prints the entry to paste. Invalid JSON in an existing config is a clear error that leaves the file untouched, writes are atomic, and a re-run leaves one entry. An existing `pyrite` entry is never silently changed beyond its command path. A server that isn't Pyrite's, or a Pyrite entry carrying env, a tier you didn't name, extra args or other settings, stops the command, which names what differs (env keys, never values). `--force` replaces it and lists what it dropped. The same rule applies in Claude Code, where a failed re-run restores the previous entry. A config with a duplicate key or a number JSON cannot write back (NaN, Infinity, 1e400) is refused untouched. Each client is reported as configured or failed (`--format json` too), and the exit code is 1 if any failed. A symlinked config is written through the link. (#582)
