A version list no longer offers a version the read refuses: `pyrite index build --with-attribution` deletes an entry's version row only on a positive fact (git read the file at the row's path in that commit and it holds another entry, or the stored path is unsafe), so a stale row such as another entry's commit at a reused path is no longer listed and then refused with a 404. A row git cannot read (a missing or corrupt commit, a shallow-clone boundary, a timeout) is kept, as is one whose path is absent from its commit; the read still refuses those. Reading a version that is not valid UTF-8 now returns not-found instead of failing (#453).
