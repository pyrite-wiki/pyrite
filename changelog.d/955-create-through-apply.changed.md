- **A new entry's file is written by the same operations as an update (ADR-0042 decision 13; #955, B6 C2).** Every create (`pyrite create`, `add`, `import`, `task create`, MCP `kb_create`/`kb_bulk_create`, REST `POST /api/entries`, the extensions' creates) now builds the file as `---`, `id:`, `---`, the body, and one operation per key of the type's frontmatter in order, through the same writer an update uses, published only if nothing is at the path (two creates of one id still give one file and one refusal, inside and outside git). The type decides which values a new file gets, never its bytes: no YAML emitter renders the document. Spelling is unchanged except that `id:` is always the first key and an empty string is written `""` rather than `''`.
