- **A field the KB's schema declares as a list holds a list on every surface.** A scalar sent to a field typed `list`, `multi-select` or `tags` (core's `person.affiliations` and `event.actors`, or one a kb.yaml or plugin declares) is stored as a one-item list by the CLI, MCP (`kb_create`, `kb_bulk_create`, `kb_update`) and REST (`POST`, `PUT`, `PATCH /api/entries`) alike; before, a scalar was stored as a string, which blocked a later `--append`. **The CLI no longer splits a `-f` value on commas:** `-f 'affiliations=City A, Inc.'` stores the one item `City A, Inc.` (0.26.3 stored `City A` and `Inc.`); several values go as a JSON array, `-f 'k=["a", "b"]'`. Naming the same `-f` key twice on `create` or `update` is refused (`VALIDATION_FAILED`) instead of silently keeping the last value. `qa validate` and the write path's warnings now report a declared list field whose file value is not a list (`expected list`), with `validation.enforce`'s severity; such a file is never rewritten (#1502).
