The Postgres backend no longer builds the HNSW index on `entry.embedding`. Since #1401 semantic search on Postgres has been an exact nearest-neighbour scan that never used the index, which was still maintained on every write. An existing database drops the index at its next start (alembic revision 013, run by the startup schema upgrade); a new database never creates it. Semantic search answers are unchanged (exact), and writes are cheaper. SQLite is unaffected. (#1822)
