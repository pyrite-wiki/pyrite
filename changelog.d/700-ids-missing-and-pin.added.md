- `pyrite ids missing -k <kb>` lists every file with no `id:` line, with the id it has today (from its title), files that share an id, and files it could not read. `pyrite ids pin -k <kb>` adds exactly one line, `id: <that id>`, as the last line of each such file's frontmatter, and changes no other byte (CRLF, comments, key order and quoting are kept; the result is re-read and the file refused if anything else would change). `--dry-run` prints the plan and writes nothing. Files that share an id are never resolved for you: the group is left untouched until you keep one and `--rename <path>=<id>` the others. Both take `--format json`; both exit `0` when nothing is left, `3` when files remain outside the id contract, `1` on an error. **Before the release that switches id-less files to path ids, follow [docs/pinning-entry-ids.md](docs/pinning-entry-ids.md)** so nothing that links to them changes (ADR-0042).
