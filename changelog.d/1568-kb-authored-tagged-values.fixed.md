- `pyrite orient` (MCP `kb_orient`, REST orient) now returns a `kb.yaml` value written with the string tag, such as `guidelines: !!str 12`, as the string `"12"` under `kb_authored`, as the quoted form already was; before, it was left out and listed in `malformed` as a kind JSON cannot carry. A mapping whose keys are written `!!str 1: x` now comes back with the string key `"1"`; before it was left out under "a mapping with a key that is not a string". If two keys of one mapping are then the same string (`!!str a: 1` beside `a: 2`), the whole value is left out and listed in `malformed` as "a mapping with two keys that are the same string", never merged with one value lost. If you upgrade with a mapping or list under a `kb_authored` key that carries a tag the loader keeps (a local tag such as `!note`, a URI tag, or `!!str` on a mapping or list) or a merge source with such a tag (`<<: !note {...}`), it was returned with the tag silently dropped and is now left out whole and listed in `malformed`, with the same one reason a tagged scalar gets and without repeating the tag; remove the tag to get it back. The core tags YAML itself defines are read as YAML defines them and returned (`!!int "12"` as `12`, `!!bool yes` as `true`, `!!map` and `!!seq` as a plain mapping and list). A number too large for JSON (`1.0e+400`) is still left out, now with the reason "a number too large for JSON (it reads as infinite)" in place of "a NaN or infinite number". Two limits remain: a tag on a list of merge sources (`<<: !note [{a: 1}]`) is gone by the time Pyrite sees the value, so it is merged with the tag dropped, and a recursive alias still comes back with `null` where it recurses, as the YAML loader reads it (#1602) (#1568).
