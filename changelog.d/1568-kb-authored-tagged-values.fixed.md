- `pyrite orient` (MCP `kb_orient`, REST orient) now returns a `kb.yaml` value written with the string tag, such as `guidelines: !!str 12`, as the string `"12"` under `kb_authored`, as the quoted form already was; before, it was left out and listed in `malformed` as a kind JSON cannot carry. Every other explicit YAML tag (a local tag such as `!note`, a URI tag, `!!str` on a mapping or list) is now treated one way on a scalar, a mapping and a list: the value is left out whole and listed in `malformed` with one reason that does not repeat the tag. If you upgrade with a mapping or list under a `kb_authored` key that carries a local tag, it was returned with the tag silently dropped and is now withheld and listed in `malformed`; remove the tag to get it back. A number too large for JSON (`1.0e+400`) is still left out, now with the reason "a number too large for JSON (it reads as infinite)" in place of "a NaN or infinite number". A recursive alias still comes back with `null` where it recurses, as the YAML loader reads it (#1602) (#1568).
