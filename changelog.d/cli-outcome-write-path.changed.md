**`pyrite create`, `add`, `update`, `rename`, `link` and the seven `pyrite links` commands are on the outcome contract (ADR-0046, #303): they print JSON by default and one place, the root, prints their result and sets the exit code.** `create`, `add` and `link` used to print text (`Created: <id>`, `Linked: ...`) and the `links` commands (`check`, `bulk-create`, `suggest`, `discover`, `batch-suggest`, `orphans`, `asymmetric`) defaulted to a rich view. Pass `--format rich`, or set `PYRITE_FORMAT=rich` once (these commands now read it), to get the text back; `--format rich` output is unchanged. `pyrite get` and `pyrite delete` are not migrated: `get` keeps `--format markdown` and `csv`, and `delete` asks a question, which a command on the contract may not do.

What else you can observe:
- The shared `--format` takes `json`, `yaml` and `rich`. `update --format yaml` prints YAML (it printed JSON). `--format markdown` or `csv`, or any other value, is a usage error (exit 2) on `update` and `rename` (they printed JSON and exited 0, whatever the value) and on every `links` command (a Python repr and a one-row dump).
- A success carries an additive `outcome` key (`done`, `partial`, `nothing`); a refusal is the error shape plus `"outcome": "error"`. A success document is printed indented, as the `task` commands print theirs, and a refusal compact; both are the root's one serialiser, not chosen per command. `update` and `rename` used to print one compact line.
- A refusal reports its own class's code where these commands printed a bare `ERROR`: a read-only KB is `KB_READ_ONLY` on `create`, `add`, `update`, `rename`, `link` and `links bulk-create` (that one said `READ_ONLY`), and `rename` of a missing entry is `NOT_FOUND` and of a taken or equal id `VALIDATION_FAILED`. `links bulk-create` on an unknown KB keeps its hint (`Run pyrite kb list`). A crash in one of these commands is one `NO_OUTCOME` line naming the exception (for example `add <directory>`), not a traceback.
- `links asymmetric` given both or neither of `-k` and `--kb-a/--kb-b` is a `VALIDATION_FAILED` refusal on stdout, exit 1 (it was a usage line on stderr, exit 2).
- `link --bidi` whose inverse fails: the message is now on stdout in `--format rich` (it was stderr), the outcome is `partial` and the exit is still 3, and the JSON lists the failure under `failed`.
- `create --template` prints `{"template": ...}` in JSON; `--format rich` prints the skeleton as before. `create --link` with a link that does not resolve still keeps the entry and exits 3; the JSON now has `linked` and `failed_links` (each with its `finish_up` command).
- `links bulk-create` accepts `--format`; its JSON has the counts and one entry per spec under `results`. A batch of zero items is `done` (exit 0), every item refused is `nothing` (1) and some refused `partial` (3), as before.
