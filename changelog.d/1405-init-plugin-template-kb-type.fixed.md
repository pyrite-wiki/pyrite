- `pyrite init --template <name>` now registers the new KB with the plugin's KB type when an installed plugin supplies that template and declares a KB type of the same name (`software`, `zettelkasten`, `encyclopedia`, `social`, `journalism-investigation`, `known-entities`), so its validators, save hooks and `orient` block run, as for the same files added with `pyrite kb add <path> --type <type>`. Before, every such KB was registered `generic`. Built-in templates, `--schema-file` and an already-registered name behave as before. A KB made by `init` before this change stays `generic`: run `pyrite config` to find the registry `config.yaml`, change that KB's `kb_type:` to the plugin's type, and its files are untouched. (`pyrite kb remove` does not work for it, because `init` registered it in `config.yaml`.) Thanks to @swastiktawate (#1405, #1408).
