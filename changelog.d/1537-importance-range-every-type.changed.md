- **`importance` is 1 to 10 on every entry type, on every write.** A create, update or `pyrite add` that sets `importance` outside 1-10 (0, 11, -5, 99) is now refused with `VALIDATION_FAILED` and an `errors` row naming `importance`, and no file is written or changed, on the CLI (`-f importance=`) and MCP `kb_create` / `kb_update`. It was refused only for `event` entries; any other type stored the value and `pyrite qa validate` then warned about what Pyrite had just written. A value already in a file is still the file's: an update of another field keeps it and reports it as a warning ("violation already on disk; kept"). A hand-written file with `importance: 99` is refused by `pyrite add`, as an event file already was (#1537).
