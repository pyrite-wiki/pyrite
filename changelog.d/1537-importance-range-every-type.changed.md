- **A write no longer stores an `importance` that is a number outside 1 to 10 or not a number, on any entry type.** Until now only `event` entries refused one; every other type stored it, and `pyrite qa validate` then warned about what Pyrite had just written. Now a create, an update that sets it, and `pyrite add` of a file that holds it are refused with `VALIDATION_FAILED` and an `errors` row naming `importance` (`rule: range`, `expected: 1-10`), and no file is written or changed, on the CLI (`-f importance=`) and on MCP `kb_create` / `kb_update`. What changes for a non-event entry: `0`, `11`, `-5`, `99` and 30-digit numbers are refused (they were stored); `update -f importance=high` or `=abc`, and an MCP `kb_update` with a non-number `importance`, are refused (they wrote the text into the file as given); `true`, `false`, `.inf`, `-.inf`, `.nan`, a list, a mapping and a date count as non-numbers and are refused too, and `true` no longer passes as 1 on an event; `pyrite add` of a file whose `importance` is `high`, `[5]`, `{a: 1}`, `0`, `true`, `.inf` or any other non-number or out-of-range value is refused (it was accepted). A numeric string (`"5"`, `" 5 "`, `"05"`) and a whole-valued float (`5.0`, `10.0`) are accepted, as before. A blank or null `importance:` in a file is absent, not a violation: `pyrite add` accepts it and an update of another field says nothing about it.
- **A value already in a file is kept and reported.** An update of another field on a file whose `importance` is out of range or not a number succeeds and returns a "violation already on disk; kept" warning, and never touches that line. On an event, `.inf` and `-.inf` used to crash that update (`NO_OUTCOME` on the CLI, `INTERNAL` on MCP); they now answer as every other value does. The one value that still stops it is a 30-digit whole number, which the index cannot store (the command answers `NO_OUTCOME`; it did on 0.26.3 too).
- **Two limits, unchanged:** `create -f importance=high` (or `abc`, `.inf`, `true`, a blank) still stores the default 5 or 1 without saying so, and `update -f importance=5.5` still writes `5.5` as given.
- In a `journalism-investigation` KB the refusal used to come from the plugin as `SCHEMA_VIOLATION` (`SchemaViolationError`, a row with no `rule`); it now comes from the model as `VALIDATION_FAILED` (`ValidationError`), the same answer as every other type (#1537).
