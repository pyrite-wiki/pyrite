- **An entry carrying a YAML timestamp is indexed (#951).** An entry with `date: 2025-06-01T00:00:00+00:00` (an ADR, an event, a task's `start_date`, `end_date`, `due_date` or `assigned_at`), a source whose `date` is a timestamp, or a tag that reads as one, was skipped by `index build` and `index sync` with only a log warning, because the loader's timestamp type could not be bound to the index; the entry was invisible to `get`, search and lists. Every such value is now bound as text in the one form the index has always stored, `2025-06-01` or `2025-06-01T00:00:00+00:00`, whatever the file's spelling, so rows indexed before this fix still sort with the new ones. A read of the entry reports the file's own spelling for its fields, tags and sources (`2025-06-01T00:00:00+00:00` for a file spelled with `T`, `2025-06-01 00:00:00` for one spelled with a space), not the index's; a value under `metadata:` is returned as the index's JSON spells it (`T`).
