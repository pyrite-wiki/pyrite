`index health` now reports files it cannot read (`unreadable_files`, including a file in a folder the process cannot search) and index rows whose id no file holds any more (`orphaned_entries`), and marks either unhealthy instead of silently passing; `pyrite-admin index health` counts both. **Behaviour change:** a file with an encoding or permission failure used to be listed under `malformed_frontmatter` (status warning, exit 0); it now moves to `unreadable_files` (status unhealthy, exit 1).
