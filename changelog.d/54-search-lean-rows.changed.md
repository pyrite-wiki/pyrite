**`pyrite search` and `pyrite-read search` results are lean by default (#54).** Each result row now carries `id`, `kb_name`, `entry_type`, `title`, `snippet` and the score the mode produced (`rank` for keyword, `similarity` for semantic, `rank`, `rrf_score`, `similarity` and `legs` for hybrid); it used to carry every index column (`file_path`, `summary`, `metadata`, `created_at`, `updated_at`, `indexed_at`, `created_by`, `modified_by`, `date`, `importance`, `status`, `location`, `lifecycle`) and, in hybrid, `distance`. The page-level keys (`match`, `match_basis`, `legs_run`, `keyword_match`, `warnings`, `query`, `count`) are unchanged. **To get the old output back: `--fields '*'`, or `export PYRITE_SEARCH_FIELDS='*'`** for every search in that shell; a comma list (`title,date,status`) picks fields, and `--fields` wins over the variable. A variable naming a field no row carries is refused with exit 2. A script that reads a dropped key now gets a missing key (a `KeyError`), not a wrong value. `--include-body` adds `body` to the lean row. CSV drops its `date` and `importance` columns and gains the score column; Markdown output is unchanged; Rich drops the Date column. MCP `kb_search` and REST `GET /api/search` are unchanged and still return the whole row. ADR-0034 records the changed default as a proposed amendment.
