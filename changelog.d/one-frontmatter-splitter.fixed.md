One rule now decides where a file's frontmatter ends, and every reader follows it. The reference is Hugo and YAML, not the old loader.

Files that read differently, for the better: a BOM, leading blank lines, `--- ` or `--- # comment` on the opening line, blanks or a tab after the closing `---`, and an indented `---` inside a block scalar or a `---` inside a quoted value are all read correctly now by `pyrite schema validate`, `create --body-file`, `add_entry_from_file`, templates, the markdown importer, collection export, the cascade and journalism alias readers, `ids pin` and the cascade migration scripts. A typed entry whose file starts with a BOM, or whose closing `---` has trailing blanks, loads as its own type instead of an `event`. The importer no longer invents a second entry from a horizontal rule in the body, and reads an entry with no body and no final newline. `pyrite export` of a collection no longer builds an entry out of prose that has two `---` rules.

Files that are now refused, visibly, with a typed error naming the line: a column-0 line before the closing delimiter that starts with `---` but is not one (`----`, `---x`, `---` + NBSP; Hugo reads these as a closer plus body), TOML (`+++`) and JSON (`{`) frontmatter (Hugo reads them), and frontmatter that never closes. `create --body-file` and `--stdin` exit with an error on these instead of storing the YAML as the body; the importer raises instead of dropping the frontmatter of an entry whose YAML does not parse; `list_templates` skips such a template with a warning instead of failing. A `# comment` after a delimiter now belongs to the delimiter line. The cascade migration scripts still write with LF line endings. `pyrite index build` on files without these shapes gives the same index as before.
