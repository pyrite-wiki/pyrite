- **One task with a word priority no longer fails every task listing** (#554). `pyrite task list` and every cross-KB task listing ended with `invalid literal for int() with base 10: 'medium'` when any task in any KB had `priority: medium`. A task's priority is now read on its 1-10 scale wherever it is read: `low`/`medium`/`high`/`critical` as 3/5/7/9, a whole number however written (`7`, `'7'`, `7.0`) as that number, anything else as the default 5, each with a logged warning naming the task; the file keeps the value as written. `pyrite qa validate` reports a task whose priority is not an integer from 1 to 10 (rule `task_priority`, naming the file), and its schema check now sees the fields a core type keeps outside `metadata` (a task's `priority`, `assignee`, `due_date`...), which it used to report as missing. An existing index keeps the old value of an unchanged file, because `pyrite index sync` re-reads only files whose content changed: run `pyrite index build` (or `pyrite index build -k <kb>`) once after upgrading to re-read every file.
