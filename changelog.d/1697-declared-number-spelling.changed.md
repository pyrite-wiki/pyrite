- A declared `number` whose file spelling is not the number's own `repr` now reads as text on MCP, REST and the CLI, where it used to read as a JSON number. `7.50`, `1.5e10` and `.5` come back as the spelling the current YAML loader reproduces (`"7.50"`, `"1.5e10"`, `".5"`). A spelling that loader reproduces and whose text is the number's own `repr` (`7`, `2.5`, `7.0`) still reads as a JSON number. The loader does not keep every source spelling: a file's `1_000.5` is stored and read as `01000.5`. An index built before this upgrade keeps the old JSON number for a file whose bytes have not changed, so a single read (it parses the file) can disagree with list and search (they return the stored row) until the rows are rewritten. After upgrading, run `pyrite index build`. `pyrite index sync` re-reads only a file whose stat moved, or whose content hash changed when `--verify` is set, so it leaves an unchanged file's old row until that file is next edited.
