- **Every write of an entry file is operations on its own bytes (#955, B6 P4).** The last four whole-file writers now name what they change and leave the rest as written: `pyrite rename` sets the new `id:` (and stamps `updated_at` where the file carries it) and rewrites `[[old]]` wikilinks only where they are, in a body or a frontmatter value, keeping every comment and a CRLF file's line endings; `pyrite schema migrate` writes exactly what the migration changed (a key added, changed or dropped, and `_schema_version`) instead of re-emitting the entry, and now actually writes a migration's result rather than only stamping the version; `pyrite ids pin` takes the entry's momentary lock around its write, so a pin and an update of one file cannot interleave; software-kb's `migrate-standards` sets the type and unsets `enforced` whatever follows them on the line, keeps the file's line endings, and refuses to overwrite a file already at the new path. The model's own `save` and markdown emitter are gone: a create's text is built onto a skeleton, and a write that changed meanwhile is a `CONFLICT`. A `created_at` or `updated_at` sent back in another spelling of the same instant (a read's `2026-01-15` for a bare date) is the file's value and writes nothing.
