- **An update no longer deletes or rewrites frontmatter keys the request does not name** (#557). A key whose value Pyrite's model cannot represent -- a `provenance:` block of a KB's own shape, `sources: a book`, `importance: high`, a `links: [a, b]` shorthand -- used to be dropped or rewritten by every `pyrite update`, REST `PATCH`/`PUT`, MCP `kb_update`, `task update` or `link` on that entry, while the command reported success. The file's value is now written back exactly as it was unless the field itself is changed. Naming a Pyrite-managed key such as `provenance` is still refused, before anything is written, and the message now says to rename the file's key. One case remains: an MCP client that sends a whole `kb_get` result back to `kb_update` names every field, so Pyrite's reading of each one is written (`importance: high` becomes `5`); send only the fields you change (#561).
