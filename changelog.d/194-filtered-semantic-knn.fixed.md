Filtered semantic searches on SQLite now apply caller filters (KB, type, tags, dates, `fips`, `state`, status) inside sqlite-vec's KNN query, so unrelated nearby entries no longer use the candidate budget before a selective filter is applied; archived entries that fill the nearest slots no longer empty an unfiltered search either (#194). More than 4,096 matching rows still returns at most 4,096 (sqlite-vec's ceiling on `k`), a `max_distance` cutoff can remove rows, and a caller scoped by readable KBs without naming a `kb_name` can still come back short, because that check runs after the KNN.
A search that names a KB (or any filter) now applies it inside the vector query, which costs somewhat more on a large KB, and an unfiltered search that hits the archived shortfall may run one extra query (a retry with a subquery, sometimes a size probe) that finds nothing new.
