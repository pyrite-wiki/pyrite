Every search response (CLI `--format json`, MCP `kb_search`, REST `GET /api/search`) carries `searched`, the entry parts the legs that ran read, taken from the backend that ran the search: on SQLite every FTS column (narrowed by a column filter such as `title:hawk`), on Postgres title, summary and body; `[]` when no leg ran; and for a semantic-only search `body_prefix` with `body_prefix_chars`, because the vectors hold only the start of a body. Tags and declared field values are not indexed yet, so a miss on one is not an absence (#1757).
