Every search response (CLI `--format json`, MCP `kb_search`, REST `GET /api/search`) carries `searched`, the entry parts the legs that ran read, taken from the backend that ran the search, and never more than were read: on SQLite every FTS column (narrowed to the columns an FTS5 column filter such as `title:hawk`, `"title":`, `{a b}:` or `- title:` leaves, nested filters intersecting; a query it cannot follow lists none), on Postgres title, summary and body; `[]` when no leg ran; and for a semantic-only search `body_prefix` with `body_prefix_chars`, because the vectors hold only the start of a body. `body_prefix_chars` is the character cut: the model's token window may cut sooner. Tags and declared field values are not indexed yet, so a miss on one is not an absence (#1757).
