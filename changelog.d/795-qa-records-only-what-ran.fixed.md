QA results now record only what ran (#795, #788). `qa assess --tier 2` and MCP `kb_qa_assess` used to write a `tier: 2` assessment from the tier 1 checks alone when no model was configured, or when the model call failed or gave no usable answer. `pyrite ci --tier 2` ignored the tier and passed. Now tier 2 with no model is refused with `AI_NOT_CONFIGURED`, a tier other than 1 or 2 with `INVALID_TIER`, and a model that did not answer every rubric item with `EVALUATION_FAILED`; none of these writes a record. A KB run lists such entries under `failed`. `ci --tier 2` runs the judgment rubric, one model call per entry with judgment items, and its findings count at the gate; `ci --kb` naming a KB that does not exist is refused with `KB_NOT_FOUND` instead of passing on no entries. A model finding is now a `warning` (it was `info`, which no status counted), so `tier: 2` with `qa_status: pass` means the model found nothing. `qa fix` reports a fix as `fixed` only once its write returned; a write that raised, a missing file, or a link with nothing to rewrite is listed under a new `failed` bucket, and one failure no longer stops the run. `--create-tasks` returns the tasks it could not create. Assessments written before this release cannot be told apart: a `tier: 2` record may hold tier 1 checks only.
