- **REST `PUT /api/entries/{id}` no longer rewrites a value a client echoed back unchanged** (#569). Like MCP `kb_update` before #561's fix, a caller that reads an entry and PUTs it back with one field changed rewrote `importance: high` as `5` and `tags: Foo` as `['Foo']`. PUT now routes through the same `KBService.split_echoed_update` comparison MCP uses; a field sent at the value Pyrite's own reading already has is left alone and named in the response's new `unchanged` field (`ignored` names a key a PUT may never set). Both are new fields with a default of `[]`, like the existing `warnings` field, so they always appear in the response -- empty when nothing was set aside -- and only ever name a key the client actually sent.
- **A bare-string `sources:` value is read as a one-item list instead of disappearing** (#569). `sources: https://x.org` or `sources: a book` used to parse to `[]`, silently dropping the source from the index, search and the API; it is now read the way a one-item list would be -- a URL keeping its `url`, a mapping (`sources: {title: x, url: y}`) the way a dict list item already was, any other scalar as a title. Writing the entry back without changing `sources` keeps the file's scalar form.
