- **REST `PUT /api/entries/{id}` no longer rewrites a value a client echoed back unchanged** (#569). Like MCP `kb_update` before #561's fix, a caller that reads an entry and PUTs it back with one field changed rewrote `importance: high` as `5` and `tags: Foo` as `['Foo']`. PUT now routes through the same `KBService.split_echoed_update` comparison MCP uses; a field sent at the value Pyrite's own reading already has is left alone and listed in the response's new optional `unchanged` field (`ignored`, also new and optional, lists keys a PUT may never set, such as `id`).
- **A bare-string `sources:` value is read as a one-item list instead of disappearing** (#569). `sources: https://x.org` or `sources: a book` used to parse to `[]`, silently dropping the source from the index, search and the API; it is now read the way a one-item list would be, a URL keeping its `url`. Writing the entry back without changing `sources` keeps the file's scalar form.
