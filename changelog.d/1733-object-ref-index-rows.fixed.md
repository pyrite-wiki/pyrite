- Object-ref index rows no longer vanish between writes (#1733). A write back from a read (the dedup merge) keeps the entry's `entry_ref`, `block` and `edge_endpoint` rows instead of dropping them until the next index: derived rows are replaced only by a write made from the entry's file, or one carrying the rows itself. Reads through a change-set overlay now see the refs and edge endpoints written into the diff, removals included. An edge endpoint spelled `other:x` stores the endpoint in KB `other`, by the same prefix rule as object-refs; run `pyrite index build --force` to restamp cross-KB endpoints indexed before this fix.
