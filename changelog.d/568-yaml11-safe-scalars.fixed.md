- **Frontmatter stays a string for every YAML reader, not only Pyrite's own** (#568). `pyrite update -f decision=yes` used to write `decision: yes` bare; a reader implementing YAML 1.1 (PyYAML's `safe_load`, the most common Python YAML library) resolves that to the boolean `true`, not the string `"yes"` Pyrite itself reads it as. Any string Pyrite writes -- a value, or a frontmatter key, since an undeclared key is stored as given (#407) -- that a YAML 1.1 reader would resolve to something other than a string is now quoted, at any nesting depth and inside list items: `yes`/`no`/`on`/`off` in any case, `true`/`false` in any case, `~`/`null`, and 1.1-only numbers such as sexagesimal `1:30`, `0777`, `0o17`, `1_000`. A real boolean or number stays unquoted, and a value already quoted in the file keeps its own quoting style. **Migration:** the next write of *any* entry re-quotes every such value already bare in that file, not only the field being changed -- a whole-document dump, not a line patch. The value itself does not change, only the bytes that represent it.
  - Known limit: bare `y`/`Y`/`n`/`N` are left unquoted. PyYAML's own bool resolver does not treat them as booleans (`yaml.safe_load("y")` is the string `'y'`), so this still round-trips through PyYAML, but a stricter YAML 1.1 reader -- Go's `yaml.v2`, for one -- does read bare `y`/`n` as booleans, and a Pyrite string with exactly that value will not round-trip there.
