A command that ran but did only part of what was asked no longer exits 0 (#526). Exit `3` now means "ran, did part, said which" (as `ids missing` and `ids pin` already did) and `1` means nothing was done; this amends the 0/1/2 decision on #303. `create --link` with a link that does not resolve keeps the entry and the good links, names each failed link with the `pyrite link` that finishes it, and exits 3. `index embed`, `pyrite-admin index embed`, `schema migrate`, `index reconcile`, `import`, `links bulk-create`, `init` (KB created, not indexed), `extension install --verify`, `export collection` and `search --files` exit 3 when they did some of the items and skipped or failed others, and 1 when they did none (so an offline `index embed` exits 1). The same holds for `kb commit` (a rejected commit), `task claim` (a lost claim, in JSON too), `task decompose`, `repo sync`, `link --bidi` (3 if only the forward link landed), `batch-read`, `sw prioritize`, `sw migrate-standards`, `investigation network`, `evidence-chain`, `bulk-edges` and `ftm-import`, and `pyrite-admin repo sync`, `repo unsubscribe` and `index health`. `backlinks` on an entry that does not exist is a not-found error (exit 1) in the command's format instead of "No backlinks found" with exit 0; on an entry with none, or one only linked to as `[[ghost-page]]`, it answers (an empty list or the linking entries). `pyrite-admin index embed` crashed with the semantic extra installed (it called a method that does not exist) and exited 0 without it; it now embeds, or exits 1 naming the missing extra. `schema migrate` no longer counts a file it failed to save as checked or says "All entries are up to date" after errors.
