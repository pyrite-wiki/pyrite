Semantic search on the Postgres backend no longer loses matching entries behind its vector index. With a selective filter (an entry type, a tag, a KB), the planner could serve the search from the HNSW index, which looks at only the 40 nearest embeddings before filtering. The result then came back empty or short, depending on table statistics, without saying it was capped. The search is now an exact nearest-neighbour scan over every row the filters admit, and rows at equal distance come back in a fixed order. (#1401)
