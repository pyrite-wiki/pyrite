- **Sending a `kb_get` result back to MCP `kb_update` changes only what you changed** (#561). A field still at the value the read returned is not written and is listed in the result's new `unchanged` field (apart from `ignored`, which names keys no update writes), so `importance: high` is no longer rewritten as `5` and a task no longer grows `importance: 5` and `priority: '5'`. Updating an event's `status` (echoed or set) no longer fails with `'str' object has no attribute 'value'`; an unknown status is refused with the allowed values. `tags: Foo` (and `aliases: Foo`) is read as one tag instead of its characters, and a bare URL in `sources:` is read as the source's URL. An existing index keeps the character tags and empty source URLs of files that have not changed since, because `pyrite index sync` re-reads only changed files: run `pyrite index build` (or `pyrite index build -k <kb>`) once after upgrading.
