- A symbolic link inside a KB to another entry file of the same KB (`sub/alias.md -> ../a.md`, relative or absolute, in any folder, or a chain of links) is now an alias of that entry: the entry is read once, at the real file, and `pyrite index sync` and `pyrite index health` list the link under a new `aliases` key (`{kb, path, target}`) instead of reporting a duplicate id. Before, sync said "Duplicate ids: 1", the first path by name could be indexed in place of the real file, and a lookup by id could return the link. Pyrite never rewrites or removes the link: `pyrite delete` (and MCP `kb_delete`, REST `DELETE /api/entries/{id}`) now removes the entry's real file only, keeps every in-KB link to it, and names them in a new `links_left` list and in `warnings` (before, it removed the link too), even when an index built by an earlier version still names the link as the entry's file. An update that would move such a file into another templated folder, and `pyrite index reconcile --apply`, leave the file in place and say which link names it. A link inside the KB with nothing at the path it names is reported under a new `dangling_links` key, a health warning, no longer an unreadable file that made `pyrite index health` unhealthy. A link to a file the walk skips, a link that leaves the KB, a link loop and a hard link are handled as before. (#1262)
