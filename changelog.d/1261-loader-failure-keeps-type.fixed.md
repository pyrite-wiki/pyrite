- A file whose type's loader refuses it (a value it will not convert, such as a `backlog_item` with `rank: .inf`; a `task` whose `metadata:` is not a mapping; a plugin loader's own check) is no longer read as an `event`. It used to be indexed silently as one, so such a `backlog_item` disappeared from `pyrite sw backlog`. Now `pyrite index sync` and `pyrite index health` list it as malformed, naming the file and the loader's message. `pyrite get`, `pyrite-read get`, MCP `kb_get` and REST `GET /api/entries/{id}` return it as the type it declares, with a `load_problems` list naming each refused field; a refused field is absent from the reply (REST leaves the column out, and a list is never `null`), never shown as the type's default. Every write to such a file (update, delete, link, rename, task claim and the other task commands, a plugin's write) is refused with `ENTRY_UNREADABLE` (REST 422) naming the file, its type, the field and the loader's message, and nothing is written; fix the field by hand. A read that cannot be narrowed to fields answers `ENTRY_UNREADABLE` rather than "not found". A file whose frontmatter is empty (`---` then `---`) loads as a note, like any file with no `type:`. (ADR-0042 decision 8a, #1261)
