- A value in a field `kb.yaml` declares `object-ref` now indexes as the entry it names in four spellings: `x` and `[[x]]` give one reference to `x` in the same KB, and `other:x` and `[[other:x]]` give one reference to `x` in the KB `other` (a registered KB's full name or shortname, the check wikilinks use). Any other value, including one with a colon and no registered KB before it (`doi:10.1000-x`, `https://ex.org/x`), is the whole id in the same KB, as before. An empty `[[]]` is no reference, and a list that names one entry twice gives one reference. Before, `[[x]]` and `other:x` were stored as written, in the source KB, so they matched no entry and the reverse lookup (`get_refs_to`) missed the source. Not handled, and no worse than before: `[[x|text]]`, `[[x#h]]`, `[[x^b]]`, a prefix with uppercase letters or `_`, and an unquoted YAML `[[x]]` (YAML reads it as a nested list). Only derived index rows change: no entry file is written. After upgrading, run `pyrite index build` to repopulate the existing rows: `pyrite index sync` re-reads only files that changed, so it leaves rows already indexed as written until their file is next edited.
