- A value in a field `kb.yaml` declares `object-ref` is now indexed as the entry it names, in any spelling. `x` and `[[x]]` give one reference to `x` in the same KB, and `other:x` and `[[other:x]]` give one reference to `x` in the KB the prefix `other` names (the rule `[[other:x]]` wikilinks use; a prefix that names no KB stays as written, so the reference points at nothing). An empty `[[]]` is no reference, and a list that names one entry twice gives one reference. Before, `[[x]]` and `other:x` were stored as written, in the source KB, so they matched no entry and the reverse lookup (`get_refs_to`) missed the source. Only derived index rows change: no entry file is written. After upgrading, run `pyrite index build` to repopulate the existing rows: `pyrite index sync` re-reads only files that changed, so it leaves rows already indexed as written until their file is next edited.
