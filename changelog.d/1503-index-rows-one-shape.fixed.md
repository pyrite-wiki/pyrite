- A field now has one JSON type whichever index reader returns it. `metadata` is always an object and `aliases` always a list; they used to be JSON text on MCP `kb_find_by_status`, `kb_find_by_assignee`, `kb_find_overdue`, `kb_find_by_location` and `kb_search` (keyword and semantic legs), on `pyrite search --fields '*'`, on REST `/api/search` with `fields=metadata`, and on the REST folder-collection route (`aliases` only). A NULL `metadata` reads `{}`. No reader gains or loses a key. A column field declared a number reads as a number on the list, find and search readers and on the single read (`kb_get`, `pyrite get`, REST `/api/entries/{id}`), where all of them used to return text: a task's `priority` (now declared a number, so `kb_get` agrees with `task_list`) and any field a `kb.yaml` declares a `number`; a field declared a `checkbox` reads as a boolean. Only plain ASCII whole numbers and decimals are read as numbers (`7`, `2.5`); `"007"`, `"+7"`, `"1e3"` and the like stay text. Sending a value read back through `kb_update`, `pyrite update -f` or REST PATCH used to rewrite `priority: 7` as `priority: "7"`; it now leaves the file as it was. Limit: the index cannot tell `7` from `"7"`, so a quoted `"7"` in a field declared a number reads as 7, and writing that 7 back stores it without the quotes; `pyrite qa validate` now reports such a value (`number_as_text`). `kb_timeline` still returns `date` and `location` as text.
