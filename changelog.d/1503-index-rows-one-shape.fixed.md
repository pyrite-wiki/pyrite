- A field now has one JSON type whichever index reader returns it. `metadata` is always an object and `aliases` always a list; they used to be JSON text on MCP `kb_find_by_status`, `kb_find_by_assignee`, `kb_find_overdue`, `kb_find_by_location` and `kb_search` (keyword and semantic legs), on `pyrite search --fields '*'`, on REST `/api/search` with `fields=metadata`, and on the REST folder-collection route (`aliases` only). A NULL `metadata` reads `{}`. No reader gains or loses a key. A column field declared a number reads as a number on the list, find and search readers and on the single read (`kb_get`, `pyrite get`, REST `/api/entries/{id}`), where all of them used to return text: a task's `priority` (now declared a number, so `kb_get` agrees with `task_list`) and any field a `kb.yaml` declares a `number`; a field declared a `checkbox` reads as a boolean. Only plain ASCII whole numbers and decimals are read as numbers (`7`, `2.5`); `"007"`, `"+7"`, `"1e3"` and the like stay text, except in a task's `priority`, which reads as the task model's integer whatever its spelling. Sending a value read back through `kb_update`, `pyrite update -f` or REST PATCH used to rewrite `priority: 7` as `priority: "7"`; it now leaves the file as it was, except in four stated cases (`docs/json-contracts.md`, "Entry row shape"): a quoted `"7"` in a field declared a number reads 7 and is written back as `7`; a task's `priority` spelled otherwise than as a whole number (`high`, `"007"`) is written back as the integer it reads as (it used to be written back quoted); a quoted `"true"` or `"1"` in a field declared a checkbox is written back as `true`; and `-7` or `0.00001` in a field declared a number reads as text and is written back quoted, as before. `pyrite qa validate` now reports numeric text in a field declared a number (`number_as_text`), saying what Pyrite reads it as. `kb_timeline` still returns `date` and `location` as text. REST's `status` and `date` fields carry the declared type. (#1503)
