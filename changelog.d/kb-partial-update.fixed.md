- **`PUT /api/kbs/{name}` no longer erases a KB's metadata field you did not send, and no longer drops what it cannot apply (#521).** Sending only `description` used to fail with a database error, and sending only `kb_type` wiped the description. An omitted field is now left unchanged and `description: null` clears the description. A `kb_type` that is `null` or blank, a key the route does not take (a typo, or `default_role`, which has its own route), a value of the wrong type, or a body that is not an object is refused with `VALIDATION_FAILED` and nothing is written; it used to be stored or silently ignored with `"updated": true`.
