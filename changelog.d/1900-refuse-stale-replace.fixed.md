- **Entry updates carrying a stale `content_hash` are refused with `CONFLICT` instead of overwriting concurrent hand edits (#1900).** `KBService.update`, MCP `kb_update`, REST `PUT`/`PATCH /api/entries/{id}`, and CLI `pyrite update --content-hash` (or `-f content_hash=<sha256>`) now compare a supplied `content_hash` against the file's current bytes on disk before applying changes, leaving the file untouched when the digest no longer matches the read it came from. A non-echo `content_hash: null` or a `content_hash` value that is not 64 lowercase hex characters is refused with `VALIDATION_FAILED`, and `pyrite update -f content_hash=...`, REST `PATCH` on `field: "content_hash"`, and `metadata.content_hash` are refused or consumed as the precondition rather than writing a `content_hash:` key into frontmatter.
