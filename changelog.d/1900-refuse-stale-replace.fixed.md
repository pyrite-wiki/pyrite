- **Entry updates carrying a stale `content_hash` are refused with `CONFLICT` instead of overwriting concurrent hand edits (#1900).** `KBService.update`, MCP `kb_update`, REST `PUT`/`PATCH /api/entries/{id}`, and CLI `pyrite update --content-hash` (or `-f content_hash=<sha256>`) now compare a supplied `content_hash` against the file's current bytes on disk before applying changes, leaving the file untouched when the digest no longer matches the read it came from.
