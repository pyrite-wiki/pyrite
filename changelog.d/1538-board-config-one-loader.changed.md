- A software KB's `board.yaml` that cannot be loaded or evaluated is now refused, instead of the gate or WIP limit it declares being skipped. The tools that read the board, MCP `sw_claim`, `sw_transition`, `sw_review` (approving), `sw_pull_next`, `sw_check_ready`, `sw_refine`, `sw_board` and `sw_review_queue`, and the `pyrite sw` commands that call them (`sw check-ready`, `sw refine`, `sw review` approving, `sw pull-next`, `sw board`), answer one refusal whose message names `board.yaml` and the kind of problem and quotes nothing from the file, and claim, move or report nothing. The code is `VALIDATION_FAILED` (not retryable), or the KB file reader's own when it refused the read (`OUTSIDE_KB_ROOT`, `KB_UNREADABLE`, `INVALID_FRONTMATTER` for the YAML limits). `kb_orient` and `pyrite orient` still answer: the software block carries `board_error`, its `board_summary` is empty and `recommended_next` is null. `pyrite sw claim`, `pyrite sw transition`, `pyrite sw submit`, MCP `sw_submit` and a `changes_requested` review change status without consulting the board (#1288). With no `board.yaml`, or a valid one, nothing changes (#1538).
- Shapes of `board.yaml` that are now refused where 0.26.3 accepted them: `wip_policy` other than `warn` or `enforce`; a criterion with no `checker`; a non-UTF-8 file; a lane with no name; an unknown criterion `type`; a `wip_limit` that is not a whole number of 0 or more; `params` that is not a mapping, or that its checker cannot use (now checked when the file is loaded, for every tool); a key Pyrite does not read, at any level; two lanes with the same name, or one status in two lanes; a gate keyed by something that is not a backlog status; a gate `name`, criterion `text` or `hint` that is not text; a file nested too deeply to load or that is not a file. `docs/plugins.md` lists what `board.yaml` may contain (#1538).
- A KB's board.yaml is read only when that KB is named; with no KB named, `sw board`, `sw pull-next` and `sw review-queue` use the built-in board. A `sw` tool called for a KB that does not resolve is refused (`KB_NOT_FOUND`); `pyrite sw pull-next -k <kb>` applies that KB's WIP limit; MCP `sw_refine` and `pyrite sw refine` with no KB are refused (#1538).
