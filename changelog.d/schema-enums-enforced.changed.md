- **Enums declared in `kb.yaml` are now enforced: a write with an off-list value is refused by default (#555).** Before, a `values:` list was silently ignored, `validation.rules` entries with `enum:` were never evaluated, and `list` fields were never checked, so validators reported clean over real drift. Now `options:` (canonical) and its alias `values:` on `select`, `multi-select` and `list` fields, list `items: {options: [...]}`, and rule-level `enum:` are all checked, the same way by writes, `qa validate`, `ci`, `schema validate` (the pre-commit hook) and `index health`. A new switch, `validation.enforce_enums` (default `true`), decides whether an off-list value is an error that refuses the write (naming the field, the value and the allowed list) or a warning. It is independent of `validation.enforce`, which still governs every other check. `allow_other: true` still makes a field's finding a warning.
- **An entry that is already off-list can be updated again (#47).** An update that leaves an off-list value as it was, including a whole read echoed back, succeeds and returns that value as a warning; this covers plugin vocabularies such as software-kb's `kind` too. Changing the field to another off-list value, or adding an off-list list element, is still refused, and create is always strict. `pyrite update` now prints the write's `warnings` in its JSON, as REST and MCP already did.
- **`pyrite index health` reports off-list values** under a new key, `off_list_values` (`{kb, id, type, field, value, allowed, origin, severity}`), including custom fields kept in an entry's metadata. A kb.yaml enum's rows make the status `unhealthy` (exit 1) when `enforce_enums` is on and `warning` when it is off. Rows from a plugin validator's enum are always `warning`; rows for an `allow_other` field are `info` and leave the status unchanged.
- **Upgrade note.** A KB that relied on the old behaviour, with data that drifts from its declared enums (including `values:` lists and rule `enum:`s that used to be ignored), now refuses off-list writes, and `index health` and `ci` report it as failing. To migrate: set `validation.enforce_enums: false` in `kb.yaml`, clean up guided by `pyrite qa validate` and `pyrite index health` (`off_list_values`), then remove the line.
