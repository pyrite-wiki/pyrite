- A KB's declared task state machine (`types.task.state_machine` in `kb.yaml`: strict with its own transition table, or relaxed with `enforce_transitions: false` and `require_reason_on_transition`) now applies to every update of a task in that KB, on `pyrite task update`, `pyrite update`, MCP and REST, and on `task claim` and `task reset`, which write through the same update. Before, those writes were always judged by the core task table, so a relaxed KB refused `open -> done` with a reason and a strict KB's own table was never consulted. Three consequences to know: `task claim` passes no reason, so in a relaxed KB with `require_reason_on_transition: true` it is refused (`open -> claimed` needs a `status_reason`); the declared machine applies to any type whose kb.yaml declares a `state_machine` and whose entry class carries a `status`, not only `task`; and in a KB whose declared machine omits a status already in use, a strict table leaves a task in that status with no way out (no declared edge leaves it), and a relaxed machine refuses a move to that status but lets a task in it move to a declared one. A KB that declares no state machine is unchanged (#1709).
