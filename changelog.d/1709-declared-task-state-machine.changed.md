- A KB's declared task state machine (`types.task.state_machine` in `kb.yaml`: strict with its own transition table, or relaxed with `enforce_transitions: false` and `require_reason_on_transition`) now applies to every update of a task in that KB, on `pyrite task update`, `pyrite update`, MCP and REST, and on `task claim` and `task reset`, which write through the same update. Before, those writes were always judged by the core task table, so a relaxed KB refused `open -> done` with a reason and a strict KB's own table was never consulted. A KB that declares no task state machine is unchanged (#1709).
