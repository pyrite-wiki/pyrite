`pyrite investigation qa --stale-days N` and the `stale_days` argument of the MCP tool `investigation_qa_report` now do something: the report gains `claims.stale_unverified`, the number of unverified claims whose `updated_at` is more than N days old (a missing or unparseable `updated_at` counts as stale, as in `pyrite qa stale`). A non-zero count adds a warning, and the table output prints it. Before, both accepted the value and ignored it.
