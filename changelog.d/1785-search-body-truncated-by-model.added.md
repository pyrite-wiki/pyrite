Every search response that carries `body_prefix_chars` (a semantic-only search, on the CLI `--format json`, MCP `kb_search` and REST `GET /api/search`) now also carries `body_truncated_by_model: true` when the embedding model's token window cut the body of an entry the response returns before that many characters, so the number is stated as the upper bound it is. The flag is derived at response time from each returned entry as it reads now, so it is true only of the entries returned. The flag was chosen over reporting the characters the model actually read because that number differs per entry: title and summary take a different share of the window for each. The flag's absence claims nothing either way (#1785).
