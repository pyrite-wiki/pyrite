Every search response that carries `body_prefix_chars` (a semantic-only search, on the CLI `--format json`, MCP `kb_search` and REST `GET /api/search`) now also carries `body_truncated_by_model: true` when the embedding model's token window was measured, while embedding in the same process, cutting an entry's body before that many characters, so the number is stated as the upper bound it is. The flag was chosen over reporting the characters the model actually read because that number differs per entry: title and summary take a different share of the window for each. The flag's absence claims nothing either way (#1785).
