- An entry whose id would give a file name the index walk skips stays findable. Before, `pyrite create --title README` (or an explicit id `README`, `readme` or `ReadMe`, a `pyrite add` or an import of a file stating `id: readme`) wrote `readme.md`; the next `pyrite index sync` dropped the entry while its file stayed on disk, and `get`, `update` and `delete` answered not found. Now the file is written as `readme-2.md` (the existing `-N` rule), it states `id: readme`, and get, update and delete by id work before and after a sync. A `kb.yaml` `subdirectory` or `file_pattern`, or a field value used by a templated `subdirectory`, that would put an entry under a dot-folder (`.private/`, a value like `.draft`), under a folder spelled `_templates` in any case (`_Templates`, `memos/_TeMpLaTeS`), at a file named `README.md` in any case, or at a name not ending in `.md` (`{id}.txt`, `{id}.MD`) is now refused with `VALIDATION_FAILED` on the CLI, REST and MCP, and nothing is written. Before, it wrote a file the next sync dropped; on macOS or Windows a mixed-case `_Templates` folder was the hand-kept `_templates` folder itself. The refusal says what you can change: the field value, the title a `file_pattern` uses, or `kb.yaml`. A field value that caused it is named in an `errors` row (`rule: "entry_path"`). A dry run (`--dry-run`, `--validate-only`, bulk validate) gives each item the answer the real write gives it, including where an earlier item of the same batch takes the `-N` name a later one would have used (one exception: on a case-insensitive disk, two items whose paths differ only in case are still compared as different names). An update whose templated move, or a `pyrite index reconcile --apply` whose move, would put the file in such a folder leaves the file where it is and says why (`not_moved`, or the reconcile's errors). An update whose templated folder is a link out of the KB is no longer reported as failed after its change was written; `not_moved` says why the file stayed. On a case-sensitive disk, a folder spelled `_Templates` (any case other than `_templates`) is no longer walked, and entry files in it that state an `id:` are named by `index health` under `unlisted_entry_files`. `pyrite index health` (and REST and MCP `kb health`) has that new warning key: a `README.md`, dot-folder or `_templates/` file whose frontmatter states an `id:`, which an earlier version may have written and the index does not list, is named with its path and reason (`readme`, `hidden`, `templates`). The exit code is unchanged. To clear it, rename the file to a name the walk lists, keep its `id:` line, then run `pyrite index sync`. A README or template with no `id:` line is yours and is not reported. (#1552)
