- One registered KB whose `kb.yaml` can be read but does not load (not UTF-8, a YAML syntax error, a duplicate key, over the YAML limits, or a top level that is not a mapping) no longer stops every command on every KB, and `pyrite serve` and `pyrite mcp` start (#1547). The other KBs work as before. The broken KB is named: `pyrite kb list` marks it, with `error_code` and the parser's words (`error_detail`); `pyrite index health` lists it under `schema_errors` with `error_code: KB_CONFIG_INVALID` and is `unhealthy`; `pyrite index sync` and `index build` skip it, keep its index rows, name it, and exit 3 (1 when nothing synced). Every operation that needs that KB's schema (get, create, update, delete, `kb schema show`/`add-type`/`remove-type`/`set`, a sync or reindex of that KB, `qa assess`) answers the new error code `KB_CONFIG_INVALID`, not retryable, with one fixed message on the CLI, MCP and REST; the parser's words reach the local CLI only. Pyrite never rewrites the file: correct `kb.yaml` by hand, then run `pyrite index sync`. Each `unreadable_kbs` row in a sync result now carries `error_code` too.
