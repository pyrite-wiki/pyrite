Git operations service using subprocess. Provides commit log, diff, blame, push, clone, pull, fork, and PR creation. Deliberately avoids gitpython/pygit2. Stateless class with all `@staticmethod` methods.

Used by version history endpoint, kb_commit/kb_push MCP tools, CLI git commands, ExportService (export-to-repo), and RepoService (subscribe, fork, sync). See [[collaboration-services]] for full method listing.

`check_remote_allowed(url, allowed_hosts)` is the one rule for where a git network operation made for a caller may go: `https://` on a host in the operator's `git_allowed_hosts` (default `github.com`), no userinfo, query, fragment or dot segments. `clone`/`clone_with_code` and `pull` always apply it -- `clone` to the URL after the account's `insteadOf` rules, `pull` to every fetch URL of the remote it uses -- and `push` applies it to every push URL when given `allowed_hosts` (export to repo does; an operator's own `kb push` to a configured remote does not, by design). All three then run git with `GIT_ALLOW_PROTOCOL=https`, LFS transfers off and `http.followRedirects=false`. `add_remote` applies the rule to the URL it stores.

**Credentials.** Every git network command (clone, pull, push) gets its credential configuration from `GitService._credentials`. For a network caller (a REST request, an MCP call with a principal) no credential source of the server account is consulted, whether or not a token is given and whatever the host: `_account_isolation_env` points `GIT_CONFIG_GLOBAL`/`GIT_CONFIG_SYSTEM` at the null device (with `GIT_CONFIG_NOSYSTEM`), sets `HOME`/`XDG_CONFIG_HOME` to an empty folder of Pyrite's (no `~/.netrc`), and empties `GIT_ASKPASS`/`SSH_ASKPASS`; the config adds `credential.helper=` and `core.askPass=`. The same environment is used for the URL lookups (`_effective_url`, `_check_remote_urls`, `_remote_credentials`), so the URL checked is the URL fetched. The command authenticates with that caller's token or with nothing. The repository's local config is still read. The local operator at the CLI (`pyrite repo subscribe`/`sync`, `pyrite kb push`; `services.acting.is_local_process`, the one switch) keeps their own helpers when no token is given. With a token, and only when every URL the command will contact -- after the account's `insteadOf` rules -- is https on GitHub, a URL-scoped inline helper (`credential.https://github.com.helper=!f() { ... }; f`) answers `get` from `PYRITE_GIT_TOKEN` and ignores `store`; it answers no other host's or proxy's prompt. Nothing is written to disk, and the token is not in argv, a remote URL or a config file. `PYRITE_GIT_TOKEN` does travel in the git child process's environment, which other processes running as the same user can read. `_sanitize_output` redacts the raw token string only (an encoded or partial form is not matched); `sanitize_error` adds absolute-path redaction for text a caller sees. `scrub_remote_credentials` removes userinfo from the https GitHub remote URLs of a workspace, and only of a repository whose top level is that workspace folder (`_is_repository_root`: a folder with no `.git` of its own, inside another repository, is left alone); each key is rewritten with `--replace-all` first, so a failed step never leaves a remote with no URL. `pull` and `push` call it, and `RepoService.scrub_workspace_remotes` runs it over every registered workspace when the REST server or the MCP server starts and from the repo commands.

**Repository programs.** Every git process Pyrite starts takes its environment from `pyrite.utils.git_hardening.git_env` (via `_git_env`, `GitService.subprocess_env`): `GIT_CONFIG_PARAMETERS` (what `git -c` sets, so it works on every git version) carries `core.fsmonitor=false` and `core.hooksPath=/dev/null`, and any inherited `GIT_CONFIG_PARAMETERS`/`GIT_CONFIG_COUNT` is dropped. Pyrite's diffs pass `--no-ext-diff --no-textconv`. Only `GitService.commit(run_hooks=True)` -- reached by the operator's own `pyrite kb commit` -- keeps the repository's commit hooks, so a hook that rejects the commit still fails that command; commits from REST and MCP run none. Filters (git-lfs), merge drivers and `gpg.program` are not guarded: Pyrite trusts a repository's local config as git does. `tests/test_kb_repo_git_commands_are_hardened.py` finds every subprocess call that starts git and fails on one without the helper.
